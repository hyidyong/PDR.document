# 시연 점검표

시연 날 아침에 위에서부터 순서대로 확인합니다. 처음 설치하는 경우는 `README.md`의 "처음 받은 사람이 실행하는 법"을 먼저 따릅니다.

## 1. 백엔드 켜기 (터미널 1)

- [ ] **새 터미널**을 엽니다. 예전 터미널에 `$env:SUPABASE_URL` 같은 값이 남아 있으면 `.env`보다 먼저 쓰입니다.
- [ ] 실행합니다.
  ```powershell
  cd backend
  .\gradlew.bat bootRun --args='--spring.profiles.active=dev'
  ```
- [ ] 로그에 `Started ModitApplication`이 보입니다.
- [ ] 로그의 `issuer=`가 실제 Supabase 주소입니다. `YOUR_PROJECT_REF`면 터미널을 새로 열고 다시 실행합니다.
- [ ] 시연이 끝날 때까지 이 터미널을 끄지 않습니다. 백엔드를 다시 켜면 신청자 제출 데이터가 사라집니다(메모리 모드).

## 2. 프론트 켜기 (터미널 2)

- [ ] `npm run dev`
- [ ] 브라우저에서 `http://localhost:5173`을 열면 A1 로그인 화면이 보입니다.
- [ ] `.env`에 `VITE_DEMO_APPLICANT_*`를 넣었다면 [사용자 데모] 버튼이 [담당자 데모] 옆에 보입니다.

## 3. 초기화

- [ ] `http://localhost:5173/?reset=1`로 엽니다. 담당자 화면에 처음 들어갈 때 담당자 Mock 데이터가 처음 상태로 돌아갑니다.
- [ ] 리허설을 했다면 브라우저를 새로고침해 A1부터 시작합니다.

## 4. 시연 순서

### 4-1. 로그인 → 역할 선택

- [ ] A1에서 시연 계정으로 로그인합니다.
- [ ] A2 역할 선택 화면이 뜹니다. 위에 "회원가입 · 1단계" 표시가 없고, 아래에 [다른 계정으로 로그인]이 있어야 합니다.

### 4-2. 신청자: 서류 점검

- [ ] [서류를 내요] → [다음]을 누르면 신청자 서류 점검 화면이 열립니다.
- [ ] 사업계획서, 물품매매계약서, 영수증 첨부철을 올리고 점검 결과를 보여줍니다. 점검 결과는 Mock입니다. 자세한 순서는 `DEMO.md`를 따릅니다.
- [ ] 브라우저 **뒤로가기**를 눌러 A2 역할 선택으로 돌아갑니다(로그인 화면까지는 돌아가지 않습니다).

### 4-3. 담당자: D1 → D5 → D6 → D7 → D9 → D1 → D10

시작 숫자(초기화 직후): 확인할 서류 **18건**, 검토 대기 **18**, 보완 요청 중 **03**, 승인 완료 **14**.

- [ ] **D1 홈:** [서류를 받아요] → [다음]을 누르면 D1 담당자 홈이 열립니다. 시작 숫자를 확인합니다. 마감 칩(D-n)은 오늘 날짜 기준입니다.
- [ ] **D5 대시보드:** "진행 중인 프로젝트"의 **2026 창업동아리 지원사업 정산**을 누릅니다.
- [ ] **D6 신청자 상세:** 맨 위 **김청년**(제출(미비), 오류 1 · 확인 1)을 엽니다. 매수인 서명·날인 누락, 계약 금액 1,350,000원 ↔ 영수증 합계 1,320,000원 불일치를 보여줍니다.
- [ ] **D7 보완 요청:** [보완 요청]을 누르고 내용을 적은 뒤 [보완 요청 보내기]를 누릅니다. "보완 요청을 보냈어요"가 보입니다.
- [ ] **D9 승인:** 위쪽 [다음 신청자] 화살표를 두 번 눌러 **정민호**(재제출)로 이동해 [승인] → [승인하기]를 누르면 D9 승인 완료 화면이 뜹니다.
  - 보완 요청을 보낸 김청년은 신청자가 다시 제출하기 전까지 승인 버튼이 잠겨 있습니다. 그래서 재제출 상태인 정민호로 승인을 보여줍니다.
- [ ] **D1 숫자 확인:** 헤더 [홈]을 누르면 확인할 서류 **16건**, 검토 대기 **16**, 보완 요청 중 **04**, 승인 완료 **15**로 바뀌어 있습니다.
  - 김청년 보완 요청: 검토 대기 −1, 보완 요청 중 +1
  - 정민호 승인: 검토 대기 −1, 승인 완료 +1
  - 숫자가 다르면 리허설 데이터가 남아 있는 것입니다. 3번 초기화를 다시 합니다.
- [ ] 최근 제출 표에서 김청년은 보완 필요, 정민호는 승인으로 바뀌어 있습니다.
- [ ] **D10 서류 현황:** 헤더 [서류 관리]를 누릅니다. 서류별 제출 / 오류 / 확인 필요 / 보완 요청 중 / 미제출이 보입니다.

  | 서류 | 시작 → 시연 후 |
  |---|---|
  | 사업계획서 | 제출 22 · 오류 0 · 확인 필요 0 · 보완 요청 중 0 · 미제출 8 (변화 없음) |
  | 물품매매계약서 | 오류 7 · 확인 필요 0 · 보완 요청 중 **3 → 4** · 미제출 8 |
  | 영수증 첨부철 | 오류 2 · 확인 필요 **6 → 5** · 보완 요청 중 **2 → 3** · 미제출 8 |

  - 김청년 보완 요청: 두 서류의 보완 요청 중 +1
  - 정민호 승인: 승인한 신청자는 확인이 끝난 것으로 보고 확인 필요에서 뺍니다(영수증 −1)
  - 행을 누르면 D5로 갑니다.
- [ ] **알림 벨:** 헤더 이름 옆 벨에 빨간 점이 있습니다. 누르면 최근 10개(제출·재제출·보완 요청·승인)가 보이고, 맨 위에 방금 보낸 **김청년 보완 요청**, **정민호 승인**이 있습니다. 열면 빨간 점이 사라지고, 항목을 누르면 그 신청자의 D6이 열립니다.
- [ ] **D11 전체 신청자:** 헤더 [신청자]를 누르면 모든 프로젝트의 신청자 **65명**이 한 표로 보입니다(창업동아리 30 · 교내 연구 활동비 15 · 해외봉사 20, 마법사로 만든 프로젝트가 있으면 그 명단도 포함).
  - 프로젝트 필터와 이름·학번 검색을 보여줍니다. 김청년 행을 누르면 D6이 열립니다.
  - 창업동아리 외 프로젝트의 행은 서류 데이터가 없어 "준비 중" 안내만 뜹니다.
- [ ] 스크롤을 내려도 맨 위 헤더(메뉴·알림·프로필)가 고정되어 보입니다. 신청자 화면 헤더도 같습니다.
- [ ] 브라우저 **뒤로가기**를 누를 때마다 D10 → D1 → … → D6 → D5 → D1 순서로 거꾸로 돌아갑니다. 계속 누르면 A2 역할 선택에서 멈춥니다.

### 4-4. 역할 바꾸기

[모드 전환] 메뉴는 없습니다. 아래 두 방법 중 하나를 씁니다.

- [ ] **브라우저 뒤로가기 → A2 역할 선택 → 다른 역할:** 뒤로가기를 눌러 A2까지 간 뒤 [서류를 내요] 또는 [서류를 받아요]를 고릅니다.
- [ ] **로그아웃 → 데모 버튼:** 오른쪽 위 프로필 → [로그아웃]을 누른 뒤 A1에서 [사용자 데모] 또는 [담당자 데모]를 누릅니다.
  - 로그아웃한 뒤에는 뒤로가기로 로그인 후 화면(A2, 신청자, 로그인한 담당자 화면)에 다시 들어갈 수 없고 A1이 보입니다. 로그인 없이 연 [담당자 데모] 화면만 다시 열립니다.

## 5. 문제가 생기면

| 상황 | 이렇게 |
|---|---|
| 로그인이 안 됨(비밀번호 오류 문구) | [사용자 데모](신청자) 또는 [담당자 데모](담당자)로 이어서 시연합니다. |
| "서버에 연결할 수 없어요" | 터미널 1에서 백엔드가 켜져 있는지 봅니다. 담당자 부분은 백엔드 없이 [담당자 데모]로 진행할 수 있습니다. |
| "이 계정은 신청 정보가 없어요" | 계정에 `app_metadata.applicant_id`가 없습니다. [서류를 받아요]로 담당자 시연을 먼저 하거나 [사용자 데모]를 씁니다. |
| 담당자 숫자·상태가 이미 바뀌어 있음 | `http://localhost:5173/?reset=1`로 다시 열고 담당자 화면에 들어갑니다. |
| 백엔드 로그 `issuer=`가 `YOUR_PROJECT_REF` | 새 터미널에서 백엔드를 다시 켭니다(1번). |
| 신청자 제출 기록이 사라짐 | 백엔드가 다시 켜진 것입니다. 메모리 모드라 되살릴 수 없으니 4-2를 처음부터 합니다. |
| 화면이 이상함 | 새로고침하면 A1부터 다시 시작합니다. 담당자 Mock 데이터는 유지됩니다. |

## 참고

- 담당자 화면(D1~D11)은 Mock 데이터이며, 브라우저 localStorage에만 저장됩니다.
- 헤더 메뉴: 홈 → D1, 프로젝트 → D5, 신청자 → D11 전체 신청자, 서류 관리 → D10. 이름 옆 벨은 최근 알림 10개.
- D1의 교내 연구 활동비 정산, 해외봉사 활동 계획서는 디자인 고정값입니다. 누르면 "준비 중" 안내만 뜹니다.
- 기능이 없는 버튼(새 프로젝트 만들기, 전체보기, 제출 링크 관리, 헤더 검색, 설정 등)은 "준비 중이에요" 안내가 뜹니다.
